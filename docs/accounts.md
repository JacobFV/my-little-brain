# Account connections

Connections supports real read-only Notion, Google Drive, and GitHub APIs. Connect verifies the account identity before it becomes available to a brain. Search and Read work from each account card and through the `connected_account` brain tool. Sharing a preview explicitly sends that content to the selected brain; tool results are also sent to the brain when it requests the connected account.

Credentials are kept in memory and browser `sessionStorage`, scoped to the configured server origin. They are not saved in localStorage, workspace backups, journals, native backups, or server storage. Reloading the same tab re-verifies the saved credential. Disconnect removes its session credential and aborts active requests; revoking access everywhere requires revocation at the provider. The trusted app server receives credentials for each request, so use a server you control and HTTPS for remote hosting. A credential expires according to its provider; reconnect when it expires. There is no automatic refresh-token persistence.

The app server access token in Settings is separate from each account credential. Both Express and the Cloudflare Worker protect `/api/accounts/*` with the existing origin and server authentication checks. Local loopback hosting follows the existing optional app-token policy; the Worker always requires its strong app token. Provider requests use fixed allowlisted endpoints, deny redirects, time out after 15 seconds, and limit response bytes to 1 MiB. Provider error bodies are discarded. No external writes or arbitrary URL fetching are supported.

## Connect with a token

- **Notion:** Create an [internal integration](https://www.notion.so/profile/integrations) with read-content capability. In each page's connection settings, share that page with the integration. Paste its integration token in Connections. Search matches titles of accessible pages, up to 20 results. Read returns the first 100 top-level blocks, up to 24,000 characters; nested or remaining blocks produce a partial-content notice. [Notion search documentation](https://developers.notion.com/reference/post-search) and [block retrieval documentation](https://developers.notion.com/reference/get-block-children).
- **Google Drive:** Supply an OAuth access token with `https://www.googleapis.com/auth/drive.readonly`, for example through the [Google OAuth Playground](https://developers.google.com/oauthplayground/) using an approved client. Enable the Drive API for that client. Search returns up to 20 Drive files. Read exports Google Docs and Slides to text, Sheets to CSV for the first sheet, or reads text/JSON/XML files. Binary formats are rejected with a useful message. Sheets exports and cut-off text are marked partial. [Drive download and export documentation](https://developers.google.com/workspace/drive/api/guides/manage-downloads).
- **GitHub:** Create a [fine-grained personal access token](https://github.com/settings/personal-access-tokens/new) with read-only Contents and Metadata permissions for the repositories to expose. Organization policy may require approval. Search filters the 100 most recently updated repositories accessible to the account by name/description, returning up to 20. Read retrieves that repository's README. Results flag possible omissions when the account has at least 100 repositories. [GitHub repository contents documentation](https://docs.github.com/en/rest/repos/contents#get-a-repository-readme).

The password field clears as soon as Connect is submitted. Tokens are never put in model tool arguments; the runtime supplies them only to the authenticated provider proxy. Source previews render as plain text. Account content is untrusted source material, not instructions for the brain.

## Optional browser sign-in

Google and Notion OAuth are available in the web app. Desktop and mobile wrappers use the token connection path; browser OAuth callbacks are not wired to native deep links.

1. Create or reuse a Google Cloud OAuth client of type **Web application**, enable Drive API, and configure the consent screen and any test users. Read-only Drive access may require Google verification for a public application.
2. Register the exact callback URI for your running **web app**, including `?account_oauth=google`, for example `http://127.0.0.1:5173/?account_oauth=google` during Vite development or `https://brain.example/?account_oauth=google` when hosted. The callback must share the web app's origin. OAuth credentials copied from another app do not automatically authorize this callback; register it in the provider console.
3. Set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, and `GOOGLE_REDIRECT_URI` in the ignored server `.env`. For Cloudflare, configure the client secret using Worker secrets and the other values as environment bindings. These keys are supported by the Worker `Env` type. Do not place client secrets in `VITE_*` settings.
4. Restart the server and open Connections in the web app. **Sign in with Google** starts Google's consent flow. The callback checks a random state, a ten-minute lifetime, and the original server endpoint. It removes the authorization code from browser history, then exchanges the code with a PKCE verifier through the authenticated server. The redirect URI is fixed by server configuration. Only the resulting short-lived access token is retained in the browser session; any refresh token is discarded.

For Notion, use a **public integration** with read-content capabilities. Set `NOTION_CLIENT_ID`, `NOTION_CLIENT_SECRET`, and `NOTION_REDIRECT_URI`, and register the exact URI, for example `http://127.0.0.1:5173/?account_oauth=notion`, in that integration's OAuth settings. **Sign in with Notion** opens Notion's page picker and consent flow. State, callback lifetime, provider, and original server are checked before the authenticated server exchanges the code using server-only Basic credentials. The verified access token is stored in the same browser session; refresh tokens are discarded. [Notion authorization documentation](https://developers.notion.com/guides/get-started/authorization).

No provider app is registered or deployed by this implementation. An unconfigured OAuth button explains the required setup; token connections remain usable. [Google web-server OAuth documentation](https://developers.google.com/identity/protocols/oauth2/web-server).

## Validation

Automated tests exercise credential validation, fixed endpoints, Drive query escaping and exports, Notion partial reads, upstream error redaction and byte limits, OAuth redirect/state constraints, server and Worker origin/auth boundaries, session credential removal, disconnection races, StrictMode initialization, and native browser fetch invocation. They use deterministic provider responses and do not access personal accounts. Live provider success requires the user's valid credential and content permissions.
