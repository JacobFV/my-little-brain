# Desktop

Electron wraps the shared web app. macOS keeps native traffic lights; Linux and Windows use web-rendered window buttons through the isolated `window.brainDesktop` preload bridge. The header must use `-webkit-app-region: drag`, with buttons marked `no-drag`, and reserve 78 px for macOS traffic lights.

From the repository root, start the web/API development servers, then run `npm run dev -w @little-brain/desktop`. The launcher waits up to 60 seconds for localhost:5173. Build the web and API first for standalone use; run `npm run build -w @little-brain/desktop` and `npx electron apps/desktop`.

`npm run package:smoke -w @little-brain/desktop` produces an unpacked host-platform app. `npm run package -w @little-brain/desktop` creates AppImage/deb on Linux, dmg on macOS, or nsis on Windows. Use each native platform for its distribution and signing. Release signing credentials are not included.

On Linux with Xvfb installed, `xvfb-run -a node apps/desktop/scripts/smoke.mjs` from the root launches the unpacked ARM64 app twice to check the bundled API, preload isolation and persisted workspace. Pass a different executable path as the last argument for another Linux architecture. This test uses a temporary app-data directory and `--no-sandbox` only for the virtual-display test process; normal desktop launches retain sandboxing.

The packaged app includes only web output, bundled server output, and Electron code. It starts the API on an ephemeral loopback port. API requests from the web app must use its current origin. No API key is bundled. Development reads the repository `.env`; packaged apps read `.env` inside Electron's `userData` directory (typically `~/.config/My Little Brain` on Linux, `~/Library/Application Support/My Little Brain` on macOS, `%APPDATA%/My Little Brain` on Windows). Set `OPENAI_API_KEY` there or in the launch environment and restart. Never put credentials in renderer environment variables.

Navigation outside the trusted local origin, popups, embedded webviews and unrelated permissions are denied. Camera and microphone permissions are eligible only for the app's own trusted local page. Native camera and microphone permission still apply on macOS; their usage descriptions are included in the packaged app. Turn camera observation on explicitly in the web interface. Object detection processes frames on the device; observation text can become conversation context.

Since the local port changes on launch, the preload restores and saves `little-brain.*` localStorage entries to `workspace.json` in the app data directory. It writes atomically, with owner-only permissions, and restores before the UI starts. Access tokens remain session-only. This local workspace file contains your conversations and settings in plaintext, like browser storage.

Local data is saved atomically in `userData/workspace.json`, independently of the ephemeral local server port. An unreadable file or an external change pauses native writes so it is preserved. Access-token/secret keys are excluded. Local Data exports the workspace and allowlisted preferences, attention and job journal. These files are not encrypted by the app.

The virtual-browser plugin opens an HTTPS-only isolated browser with an ephemeral session, no preload or Node access, and blocked popups/downloads. Microphone and camera are denied until the user explicitly enables each device for the focused session and its current HTTPS origin. Its cookies/storage are discarded when closed. The main app disables renderer background throttling so jobs continue while minimized; quitting still stops work.

Each explicitly opened browser session emits an ephemeral interaction stream to the app: a unique instance ID, lifecycle state, and JPEG previews capped at 512 pixels wide and about one frame per second, increasing to 1,200 pixels and about eight frames per second while its tablet is focused. Only that plugin window is captured, never the main window or OS screen; previews are not persisted. Closing the browser ends its interaction and clears its session. Up to eight sessions may be open.

Brain control is opt-in separately for each browser session. `openBrowser(url, {allowControl, interactionId})` defaults to manual operation. Authorized sessions support bounded `read`, HTTPS `navigate`, viewport-coordinate `click`, `type` (4,000 characters maximum) and `scroll` commands. Every action targets an existing plugin instance and is denied for manual sessions. Page summaries are untrusted external content; application model instructions must treat them as observations rather than instructions. The model never receives Node, shell, arbitrary JavaScript, OS input, or arbitrary-window capture privileges through this interface.

The focused browser tablet supports a separate trusted-user input lane, independent of model-control consent: click, text, bounded keys/modifiers and scrolling target only the explicitly focused plugin instance. Native-window focus briefly handles trusted input and returns to the app. “Open session window” exposes native site dialogs and controls. Only one tablet has focus at once.

Audio playback, microphone and camera have separate explicit switches. Device grants apply only to the same focused browser contents and current HTTPS origin; subframes on different origins remain denied. Switching focus or navigating to another origin clears grants and mutes playback. Removing a live device grant reloads the plugin page to terminate existing capture tracks. No operating-system or main-app screen capture is granted. Physical-device permission dialogs still require target-device verification.

`xvfb-run -a node apps/desktop/scripts/workspace-smoke.mjs` exercises the packaged App itself: Connections opens a session, its brain-owned object can be dragged, clicking it opens the focused display, display coordinates and the keyboard type into the isolated page, audio toggles, and closing restores the plane and mutes media. The fixture is served within the isolated test session; it sends no external actions. The script writes `/tmp/little-brain-focused-browser.png` for visual inspection.
