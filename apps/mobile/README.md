# Mobile

Expo SDK 54 / React Native 0.81 hosts the same web experience inside a native WebView, with safe areas, keyboard handling, persisted server connection, loading, error, retry and Android back navigation. Twins and conversations persist within that WebView's origin. Changing server origins selects a separate local data store; mobile is not automatic cross-device synchronization.

Run `npm run dev -w @little-brain/mobile`. Open in Expo Go on a device on the same network. The default development URL derives your computer's address from Expo and uses port 5173. Start the web server with LAN binding and keep its API proxy enabled. Override with `EXPO_PUBLIC_BRAIN_URL=https://your-brain.example.com` before running Expo, or change it in the native Connection screen. That URL is public app configuration; never put an API key there. Camera and microphone capture on a physical phone require a secure HTTPS origin; HTTP LAN development supports text and the scene.

For example, with your computer at `192.168.1.23`, run `ALLOWED_ORIGINS=http://192.168.1.23:5173 npm run dev:server`, `npm run dev -w @little-brain/web -- --host 0.0.0.0`, and `npm run dev -w @little-brain/mobile` in three terminals. The phone connects to `http://192.168.1.23:5173`; Vite forwards API requests to the computer's loopback API. Include the LAN web origin in `ALLOWED_ORIGINS` even with this proxy. Use your own LAN address.

Native development builds enable Android cleartext web traffic and iOS local-network/WebView HTTP exceptions through app configuration. Preview and production builds disable these exceptions. Expo Go uses its own native network policy. HTTP never grants secure-context media capture; use HTTPS for voice and camera observation.

Production builds require an HTTPS origin, with no embedded credentials, query or path. Deploy the built web app and API behind the same HTTPS origin with WebSocket support, set a server access token, and enter the token in the web app's Settings. The native shell only allows navigation within the chosen origin and prompts for camera or microphone capture. Android declares CAMERA and RECORD_AUDIO; iOS includes both usage descriptions. Camera observation is enabled explicitly in the web interface. Object detection processes frames on the device; observation text can become conversation context. Real-device permissions and performance must be checked on your target OS and hardware.

`npm run typecheck -w @little-brain/mobile` checks TypeScript. `npm run export -w @little-brain/mobile` creates iOS and Android JavaScript/assets in `dist`; it is not an installable binary. Run `npm run android -w @little-brain/mobile` / `npm run ios -w @little-brain/mobile` with the corresponding native SDK installed for local builds. From this directory, use `npx eas-cli init` once to link your own Expo project, configure `EXPO_PUBLIC_BRAIN_URL` for the selected EAS environment, then `npm run build:android` / `npm run build:ios`. EAS builds require your Expo account and platform signing credentials. The checked-in `eas.json` supplies development, preview and production profiles.

SDK compatibility references: [SDK 54](https://expo.dev/changelog/sdk-54), [WebView](https://docs.expo.dev/versions/v54.0.0/sdk/webview/), [AsyncStorage](https://docs.expo.dev/versions/v54.0.0/sdk/async-storage/), [safe areas](https://docs.expo.dev/versions/v54.0.0/sdk/safe-area-context/).

Local privacy: the WebView keeps an origin-scoped native AsyncStorage backup containing workspace, preferences (without access tokens), attention and background job journal. It restores before interactive work starts; switching server origins never exposes the previous server’s backup. The prior native revision is retained before replacement. Local Data exports a JSON file through the system share sheet. Device storage is not encrypted by this app. Mobile operating systems can suspend background work when the app is not foregrounded; continuous tasks resume when the app returns.
